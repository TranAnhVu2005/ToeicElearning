# TOEIC Learning — Project Context

> Tóm tắt nhanh cho agent; ưu tiên gọn và tối đa khoảng 130 dòng khi cần ghi nhận mốc triển khai. Chi tiết sản phẩm nằm trong `docs/01_OVERVIEW.md`–`docs/06_SECURITY_SPEC.md`. Mã nguồn/schema là nguồn xác nhận trạng thái thực tế.

## Mục tiêu
- Website luyện thi TOEIC thương mại: Admin (đề/user/payment/dashboard/duyệt teacher), Teacher (lớp/tài liệu/đề/assignment), Student (thi/luyện/review/lớp/notification), đề VIP/VNPAY.
- Chủ dự án đã yêu cầu tiếp tục triển khai và sửa lỗi theo các yêu cầu/đặc tả hiện hành; giữ kiến trúc và chỉ coi các mục đã chốt là phạm vi bắt buộc. Tính năng đề xuất cần được phân biệt rõ.
## Stack và entry points
- Backend: Java 17, Maven WAR, Spring Boot 4.1.0, Spring Data JPA, Spring Security, MySQL; port 8080. Hibernate SQL logging mặc định tắt, chỉ bật tường minh qua `JPA_SHOW_SQL=true` khi debug cục bộ.
- Frontend: React 19, Vite, React Router, Tailwind CSS, Axios; dev mặc định 5173; gọi `http://localhost:8080/api`.
- Mọi page route được tải bằng `React.lazy` trong `App.jsx`, có Suspense loading Neo-brutalism; build hiện tách chunk và main JS giảm từ ~789 KB xuống ~314 KB (chunk route lớn nhất hiện ~198 KB).
- Backend root package: `backend/src/main/java/com/ctu_cit_nienLuanNganh/toeicLearning/`.
- Frontend routes/layout: `frontend/src/App.jsx`; API client/auth: `frontend/src/api/apiClient.js`, `frontend/src/context/AuthContext.jsx`, `frontend/src/services/`.
- Thi: `frontend/src/pages/ExamTakePage.jsx`; soạn đề: `frontend/src/pages/admin/TestManagementPage.jsx` (file lớn, autosave/local recovery/server draft save).
- Kiến trúc cần giữ: một backend Spring Boot modular monolith dùng REST/JWT và một React/Vite SPA. Tính năng mới mở rộng cấu trúc này; không tự chuyển framework, tách microservice/BFF hay tái cấu trúc diện rộng.
## Bản đồ backend
- Modules hiện có: `auth`, `exam`, `user`, `admin`, `media`, `classroom`, `notification`; lớp học có flow tạo lớp/roster, assignment/feedback, tài liệu PDF private và đề riêng gắn classroom. Admin metrics/presence bổ sung trong module `admin`/`user`.
- Entities chính: `Role`, `User`, `Test`, `Part`, `ContextQuestion`, `Question`, `TestResult`, `UserAnswer`; thêm lớp học/tài liệu/bài tập, `PaymentTransaction`, `Notification`.
- Quan hệ đề: `Test -> ContextQuestion -> Question`; `orderIndex` là số câu bắt đầu của context, `questionNumber` là số global.
- Auth routes: POST `/api/auth/register`, `/login`, `/google`. Google ID token được xác minh chữ ký RS256 bằng JWK cache từ Google, kiểm tra issuer/audience/time/email_verified; định danh `sub` lưu unique trong `user.google_sub`; không auto-link local account theo email.
- Exam routes: GET `/api/exam/list`, `/{testID}`, `/{testID}/parts/{partID}`, authenticated `/{testID}/dictation`; API Part xác nhận đề có context thuộc Part được yêu cầu, sai đề trả `PART_NOT_FOUND`; submit lọc Part an toàn cả với dữ liệu context legacy thiếu quan hệ Part; admin list/detail ở `/api/exam/admin/**`; create/update/publish/draft/delete chỉ ADMIN.
- User routes: GET `/api/user/me`, PATCH `/api/user/updateprofile`, POST `/api/user/changepassword`, POST `/api/user/setpassword`. Google-only account có thể đặt mật khẩu local sau khi xác minh ID token Google mới tối đa 5 phút và `sub` khớp; hash BCrypt, tăng `authVersion`, yêu cầu đăng nhập lại. Profile DTO chỉ thêm cờ `hasLocalPassword`/`canSetLocalPassword`, không lộ hash hoặc Google `sub`.
- Admin routes: GET `/api/admin/users`, PATCH `/api/admin/changestatus`; GET `/api/admin/payments` tra cứu giao dịch theo trạng thái/ngày/người trả/email/mã tham chiếu, chỉ ADMIN. Media upload ADMIN/TEACHER: decode JPEG/PNG ≤5 MiB, signature/structure MP3/WAV/M4A ≤20 MiB, giới hạn chiều ảnh 8000 và 20MP, folder trong namespace app; avatar dùng cùng validation. Rate limit media 30/IP + 20/user và PDF lớp 30/IP + 10/teacher mỗi 15 phút, bucket hash MySQL. Upload chọn `resource_type` theo folder. Xóa bằng URL client đã bị gỡ; internal cleanup kiểm tra HTTPS host/account và namespace `Resource/toeic-learning/`. Fallback avatar dùng asset local, không gửi tên/email lên dịch vụ ngoài.
- Thi/review đã có backend: POST `/api/exam/submit` chấm server-side và lưu `TestResult`/`UserAnswer`; GET `/history` và `/results/{id}` chỉ trả kết quả của user hiện tại. UI có trang riêng xem lại kết quả tại `/results/{id}` với câu trả lời, đáp án, lời giải, audio/transcript; lịch sử đề dùng API thay vì dữ liệu mẫu.

## Dữ liệu đề và quy tắc cốt lõi

## Security và cấu hình
- JWT Bearer gồm subject user ID + `authVersion`; filter nạp user/role từ DB, so version và từ chối account locked. Frontend chỉ xóa phiên với 401 hoặc code khóa 2009; 403 do thiếu quyền không đăng xuất. Axios log chỉ status; `AuthContext` dọn cache user JSON hỏng. Roles: `ROLE_ADMIN`, `ROLE_USER`, `ROLE_TEACHER`.
- Security filter chain deny-by-default (`anyRequest().authenticated()`), allowlist auth/catalog/parts; admin/user routes và endpoint nhạy cảm có RBAC/method security. CSRF disable theo JWT bearer header hiện tại. CORS allowlist đọc `APP_CORS_ALLOWED_ORIGINS`, từ chối wildcard, credentials off; default localhost dev.
- Frontend API URL đọc `VITE_API_BASE_URL` (default localhost). Có `frontend/.env.example` đã được allowlist trong `.gitignore`; production cần đặt HTTPS API URL và exact frontend origin trong `APP_CORS_ALLOWED_ORIGINS`. Datasource, JWT, Cloudinary, VNPAY cấu hình qua environment; startup kiểm tra `JWT_SECRET` Base64 tối thiểu 32 byte và `JWT_EXPIRATION` dương. Google audience qua `GOOGLE_CLIENT_ID` (đồng bộ `VITE_GOOGLE_CLIENT_ID`). `.env` được ignore, không có `.env` nào đang được Git track.
- Không chép credential Cloudinary/JWT/VNPAY từ properties vào docs/log/frontend; dùng env cho cấu hình mới.
- Đọc `docs/06_SECURITY_SPEC.md` trước khi thay đổi auth/API/payment/upload/lớp/dữ liệu/deploy; đây là yêu cầu mục tiêu, không phải bảo đảm đã triển khai. Còn rủi ro cần xử lý trước production: token localStorage/JWT TTL 24 giờ, media legacy public và URL private có cửa sổ chia sẻ 2 giờ, audit coverage một phần/MFA, CSP/frontend host, proxy configuration, kiểm thử tích hợp và rà soát quyền phân phối nội dung. Backend security headers/error response hardening đã cấu hình nhưng chưa xác minh ở môi trường deploy.
